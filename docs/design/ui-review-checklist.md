# 界面自检清单 (UI Review Checklist)

> 用途：把「界面是否合格」收敛为可回答“是 / 否”的检查项，供实现自检（D）、审计（A）与浏览器验证（V）共用。
> 来源与筛选口径：[界面自检清单与视觉债治理计划](./governance/2026-10-26-ui-review-checklist-plan.md)（U1–U6 的取舍理由与执行切片）。
> 边界：本清单只覆盖 U1–U6，**不得在执行时临时扩项**；确需新增条目，先改规划文档再改本清单。

## 0. 使用方式

1. **触发**：diff 触及 `components/`、`pages/`、`layouts/`、`styles/`，或改动了用户可见文案 / 主题 / 状态色时，逐项回答 U1–U6。
2. **回答**：每项只能填「是 / 否 / 不适用」。填「不适用」必须写明理由；留空视为未检查。
3. **证据**：结论必须附证据——截图路径、`getComputedStyle` 取值、对比度计算值或 diff 扫描结果；不接受“看起来没问题”。
4. **放行**：存在任一「否」且未登记例外时，A 阶段不得放行；例外须在提交说明中写明原因与后续处置。

## U1 空态 / 加载 / 错误三态

**触发**：新增或改动列表、卡片流、抽屉、弹窗等数据面。

- [ ] 空态、加载、错误三种状态都已实现。
- [ ] 空态包含「图标 + 说明 + 主操作」；确实无需操作时写明理由。
- [ ] 空态文案描述当前对象，未复用其他模块的文案 key。
- [ ] 空表不渲染分页。
- [ ] 加载超过 300ms 使用骨架屏（列表行骨架 / 详情块骨架），不是裸 spinner + 文本。
- [ ] 错误态提供重试入口。

**证据**：空 / 加载 / 错误三态截图 + 对应 i18n key + 空表无分页的截图。

## U2 文字层级（字号 / 字重 / 颜色三轴）

**触发**：任何新增或改动的文本样式。

- [ ] 字号只取现有 8 档 token，不新增档位；阅读模式的用户字号（`--reader-font-size`，14–26px）除外。
- [ ] 新代码不写 `rem` 字号字面量（第三方覆盖、图标尺寸除外，需注明）。
- [ ] 层级至少同时使用两轴（字号 + 字重，或字号 + 颜色）。
- [ ] 正文与元信息 / 标注（不含摘要、引言）至少差一档字号，并有颜色区分。
- [ ] 同一屏没有两个视觉权重相同、语义却不同级的标题。

**字号档位**：`$font-size-xs` 0.75rem / `sm` 0.875rem / `base` 1rem / `lg` 1.125rem / `xl` 1.25rem / `2xl` 1.5rem / `3xl` 1.875rem / `4xl` 2.25rem。

**证据**：diff 中新增 `font-size` 字面量为 0；附一屏的字号 / 字重 / 颜色三轴截图。

## U3 主操作与状态可辨

**触发**：页面头部、弹窗 / 抽屉 footer、行内操作、状态标记。

- [ ] 每屏（页面 / 弹窗 / 抽屉）最多一个 primary 按钮。
- [ ] 主操作不是 ghost 变体。
- [ ] 破坏性操作使用 danger，并保留文字或可访问名。
- [ ] 状态不只靠颜色：颜色必须配文字或图标。
- [ ] 纯图标按钮具备 `label` / `aria-label`。

**证据**：弹窗首屏截图 + 图标按钮可访问名扫描 + 状态标记的文本 / 图标。

## U4 分组靠间距，边框最后

**触发**：新增卡片、面板、表单分区、列表容器。

- [ ] 同组内间距小于组间间距。
- [ ] 优先用间距或背景层次分组，不靠新增分割线 / 边框。
- [ ] 边框只用于输入框、表格分隔和确有语义的边界。
- [ ] 同一视口内带边框的嵌套容器不超过两层。

**证据**：改版截图 + 新增 `border:` 的分组理由。

## U5 阅读宽度与排版

**触发**：文章详情、关于页、长文型落地页。

- [ ] 正文行宽 60–75 个西文字符（中文 35–45 字）。
- [ ] 通过 `max-width: 65ch` 或等价宽度并居中来约束。
- [ ] 正文行高 1.6–1.8，标题行高 1.2–1.3。
- [ ] 正文与摘要 / 引言使用同一字号档（摘要 / 引言不受 U2 的“辅助文本差一档”约束）。
- [ ] 长文使用 `text-wrap: pretty`，标题使用 `text-wrap: balance`。

**证据**：1440 / 768 / 375 三档截图与行长计算。

## U6 对比度与暗色等价

**触发**：任何颜色、主题、状态色、tint 背景改动。

- [ ] 文字 / 图标在 soft / tint 底上 ≥ 4.5:1（大字号 ≥ 3:1），并给出计算值。
- [ ] 非文本边界（边框、图标、焦点环）≥ 3:1。
- [ ] soft / tint 底按混合后的实际底色计算，不只算 token 原值。
- [ ] 暗色模式已复检，同一组件在浅 / 深两态都可读。
- [ ] 未用 light tint（`--p-primary-50` / `-100`）作大面积背景（单个区块 ≥ 半屏，约 400px 高）。
- [ ] 暗色抬升面与底色至少相差两档。
- [ ] 状态色 tone 与 solid 分档，未互相顶替。

**证据**：浅 / 深两态计算值与截图；soft / tint 底须给出混合后的实际底色与对比度。
