# 2026-10-26 界面自检清单与视觉债治理计划

> 状态：候选评估（未上收）。backlog 落点见[长期主线 #11](../../plan/backlog.md)。
> 来源：以《Refactoring UI》20 条规则为参照，对 momei 现行样式栈做的一轮只读自检（静态扫描 + 7 组既有视觉基线 + 既存对比度实测）。自检记录不复述原文规则，只保留与本仓命中的结论。
> 定位：本文件是**规划**，不是清单正文。正式清单已落盘为 [界面自检清单](../ui-review-checklist.md)，判据只在清单中完整声明一次；本文件保留筛选口径、本仓证据与执行编排，不重复判据。

## 1. 背景与问题定义

项目已经越过「不知道该改哪里」的阶段：有 `--p-*` / `--caomei-*` token 桥接、视觉一致性门禁与状态色对比度实测。本轮自检的问题不是「设计原则缺失」，而是**原则没有落成可判定、可回归的检查项**，于是四类问题长期存在且不会被门禁发现：

| 类别 | 实测证据 | 对应检查项 |
|:---|:---|:---|
| 颜色**根本没渲染** | `--p-success-500` / `--p-warning-500` / `--p-error-500` / `--p-info-500` 全仓 0 定义，却支撑 24 处 `$color-*` 消费；另有 7 处 `--p-warning-color`、2 处 `--p-error-color`、1 处 `--p-text-secondary-color` 同样未定义。文章内 tip / warning / danger / info 提示块因此无颜色区分 | U6 |
| 空态错用且无设计 | `pages.posts.empty`（“暂无文章”）被评论 / 订阅 / 候补 / 分类 / 标签共 4 个文件、5 个页面复用；空表仍渲染分页 | U1 |
| 字阶失控 | 478 条 `font-size:` 声明、60 种写法（含 `inherit` / `var()` 2 处非字面量）、426 条 rem 字面量，走 token 的仅 30 处（6.3%） | U2 |
| 暗色语义反转 | `--p-primary-50` 由 `color-mix(primary, white 95%)` 生成，暗色下仍近白，34 处以 light tint 作背景（`-50` 23 / `-100` 11）；`--p-surface-0` 是底色，却有 44 处作背景消费（共 58 处引用） | U6 |

扫描口径：`rg -o … components pages layouts styles -g '*.vue' -g '*.scss' -g '*.css'`（下同）；`--p-*` 计数为源码引用数，不含 `node_modules` 与构建产物。

同时，设计文档与实现已经漂移：`docs/design/ui.md` 承诺骨架屏、移动端正文字号 16→17/18px、Inter / Noto Serif 字体，实际分别是 8 个 Skeleton 文件对 13 个文件 / 14 处 ProgressSpinner、移动端仍 `1rem`、未加载任何 webfont。这份文档目前是理念，不是规格。

## 2. 筛选口径：为什么只收 6 条

20 条不是 20 个检查项。按以下四条过滤，只保留能进清单的条目：

1. **真实**：本轮有文件 / 像素 / 计算证据，不是“原则上可能存在”。
2. **影响使用**：影响阅读、操作完成或状态判断；只影响“精致度”的不进。
3. **可判定**：能写成人工检查项或脚本断言，不依赖审美共识。
4. **不重复治理**：已由迁移方案、token 治理、上游反馈覆盖的，只引用，不另立条目。

结论：**20 条收敛为 6 个检查项**（覆盖 11 条规则）；其余 9 条按 §4 合并、降级或排除。

## 3. 清单条目

完整判据（可勾选项）见 [界面自检清单](../ui-review-checklist.md)；本节只保留筛选结论与本仓证据。

| 检查项 | 覆盖原规则 | 为什么留下（本仓证据） |
|:---|:---|:---|
| U1 空态 / 加载 / 错误三态 | 20 | 4 个文件 / 5 个后台页复用「暂无文章」；空表仍渲染分页；8 个 Skeleton 文件对 13 个文件 / 14 处 ProgressSpinner |
| U2 文字层级 | 3、4 | 478 条 `font-size:` / 60 种写法 / token 化 6.3%；10 个近邻字号并存 |
| U3 主操作与状态可辨 | 6、15 | 分类 / 标签弹窗「保存」为 ghost，与「取消」同权重（`admin-taxonomy-page.vue:298-301`） |
| U4 分组靠间距，边框最后 | 7、9、19 | 设置页五层嵌套面；扫描面 194 处 `border:` |
| U5 阅读宽度与排版 | 8、11 | 正文容器 900px − 左右 2.5rem ≈ 820px，英文约 100 字符；全仓 0 处 `ch`；正文 `1rem/1.6` 与摘要 `1.05rem/1.8` 不一致 |
| U6 对比度与暗色等价 | 14、15 + 暗色缺口 | soft 8% 实测 2.12 / 2.59 / 3.39；暗色说明卡近白（`setting-explanation-card.vue:67`） |

> U3 与 U6 都覆盖原规则 15：U3 管「非颜色冗余」，U6 管对比度。

## 4. 其余条目的处置与理由

| 原规则 | 处置 | 理由 |
|:---|:---|:---|
| 1 为设计选一种个性 | 降级为一次性设计决策 | 不是每屏可检查项；字体资产、圆角与密度的取舍应单独立项 |
| 2 别着急上色 | 不纳入 | 色板与 4 套主题预设已就位 |
| 5 非必要不用标签 | 并入 U2 / U3 | 表现为信息层级与状态可辨问题，不单列 |
| 7 从过度留白开始、9 间距有亲疏、19 慎用边框 | 合并为 U4 | 三者是同一个判断：分组是否成立 |
| 8 不必填满屏幕、11 行长与行高 | 合并为 U5 | 对本仓（博客）而言，核心是阅读宽度，不是后台满宽 |
| 10 缩放不总是等比 | 暂不纳入 | 本轮未做浏览器实测，无证据；待移动端验证后再定 |
| 12 基线对齐，不居中 | 暂不纳入 | 影响小、判定主观，易产生噪声 |
| 13 颜色比想象的多 | 由 U6 与迁移方案 token 治理覆盖 | 已有色阶与对比度门禁，不重复 |
| 14 无障碍也能好看、15 别只靠颜色 | 合并为 U6 + U3 | 对比度归 U6，非颜色冗余归 U3 |
| 16 强调色边框 | 不纳入 | 已在用（5px 左边框），且被 U4 的“边框最后”覆盖 |
| 17 图上文字先处理背景 | 不纳入 | 本仓当前无封面叠字场景 |
| 18 每样东西有适用尺寸 | 不纳入 | 属 caomei-ui 组件档位缺口，已由上游反馈跟踪 |

## 5. 执行切片

| 切片 | 内容 | 规模 | 前置 |
|:---|:---|:---|:---|
| **S0** | 落盘 `docs/design/ui-review-checklist.md`（U1–U6），并在 `ui-validator` skill 与 A 阶段审查清单中引用（不改 `AGENTS.md`） | 1 份文档 + 2 处引用 | 本计划确认 |
| **S1** | 状态色幻影 token 清零（34 处）+ 空态组件与文案（4 个文件 / 5 页）+ 空表不渲染分页 | 6–8 文件 | S0 |
| **S2** | 暗色 tint 语义（`primary-50/100` 与 `surface-0` 消费）+ 设置页嵌套盒收敛 + 主操作权重 | 8–10 文件 | S1（token 先为真） |
| **S3** | 字阶护栏（新代码只允许 8 档）+ 阅读排版（`65ch` / `text-wrap` / 正文与摘要统一） | 4–6 文件 + 规则 | S0 |
| **S4** | 视觉门禁扩容：≥2 条 reader 路由 + 带数据行基线；空态纳入基线 | 3–4 文件 + 基线 | S2、S3 |

S1 优先于 S2：先让颜色“存在”，再谈颜色“好看”。S3 的字阶替换只约束新增 / 改动文件，不做 478 处全量替换。

**S1 的范围切分**：S1 只处理状态色 / 文本语义幻影 token（`$color-{success,warning,danger,info}` 24 处 + `--p-warning-color` 7 + `--p-error-color` 2 + `--p-text-secondary-color` 1）。`--p-surface-border`（95 处 / 37 文件）与 `--p-text-color-secondary`（15 处 / 9 文件）分布在全站样式与公开页（`main.scss` / `_layout.scss` / `_rendering.scss` / 文章页等），不属单一迁移批次；按迁移方案各批「文件 → 改动点」清单决定是否顺带修正，未被 B3 / B4 覆盖的消费点回到 S1 或后续候选（[roadmap 第六十八阶段观察项②](../../plan/roadmap.md)）。

## 6. 风险与回滚

| 风险 | 处置 |
|:---|:---|
| 状态色幻影 token 修复后提示块突然出现颜色，视觉基线变化 | 在回归记录显式登记为“预期恢复”，不按回归缺陷处理 |
| 暗色 token 改动影响 4 套主题预设 | 先在 `default` + `amber` 两套验证，再覆盖 `green` / `geek` |
| 空态组件替换改变 parity 基线（基线本身多为空态） | 同一批次内更新基线并归因，不与迁移 B3/B4 批次混做 |
| 字阶护栏产生大量存量告警 | 只对新代码 / 改动文件生效，存量按批次自然收敛 |
| 阅读宽度收紧后文章页布局变化 | 先只在文章详情验证，确认导航 / 侧栏 / 阅读模式无连带回归 |

## 7. 验收标准

- **S0**：清单存在，U1–U6 判据可逐条回答“是 / 否”；`ui-validator` 与 A 阶段入口引用该清单；文档检查全绿。
- **S1**：状态色 / 文本语义幻影引用为 0（`--p-{success,warning,error,info}-color`、`$color-{success,warning,danger,info}`、`--p-text-secondary-color`）；`rgba(var(` 为 0；4 个后台组件空态文案正确；空表无分页；附截图。
- **S2**：暗色说明卡不再出现近白面板；主操作按钮为 primary；浅 / 深对比度计算值达标。
- **S3**：diff 扫描新增 `font-size` 字面量为 0；文章页行长满足[清单 U5](../ui-review-checklist.md) 的区间要求。
- **S4**：`reader` 路由 ≥ 2 条进入 parity；空态截图为基线一部分。

## 8. 非目标

- 不重做视觉风格或品牌；不做颜色体系重构（沿用现有 token 与主题预设）。
- 不引入 Tailwind / UnoCSS；不改变 PrimeVue → caomei-ui 的批次编排与锁定策略。
- 不做 478 处字号的存量全量替换；不统一 194 处边框。
- 不改动 `docs/design/ui.md` 的正文（留待迁移收尾统一改写）。
- 不购买或引入外部设计资源 / 字体资产（字体决策单独立项）。
