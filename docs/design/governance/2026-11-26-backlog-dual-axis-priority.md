# Backlog 双轴优先级决策（重要度 × 紧急度）

-   日期：2026-11-26
-   来源：issue #1098（提案），采纳为用户指令「处理 issue 中的提案」
-   落点：[规划规范 §3.5](../../standards/planning.md#35-backlog-双轴优先级候选池排序backlog-dual-axis-priority)、[backlog 候选区](../../plan/backlog.md)

## 1. 问题

`planning.md` §3.1–§3.3 的 4 维矩阵回答「是否准入近期规划」，但已进入 backlog 的候选没有排序字段：候选池只能按正文标签（如 `P2 · 长期`）或更新时间隐式排序，无法解释「先做哪一条」。

## 2. 决策

4 维矩阵与双轴评分**并存且分工**，不替换、不互相推导：

| 机制 | 回答的问题 | 输入 | 输出 |
| :--- | :--- | :--- | :--- |
| 4 维矩阵（Value / Alignment / Difficulty / Risk） | 是否准入近期规划 | 业务价值、契合度、成本、风险 | `Score` 与进入 / 确认档 / 搁置 |
| 双轴（重要度 / 紧急度） | 已入池候选按什么顺序推进 | 不做是否造成损失、是否有时间窗 | 1–5 分与首排 / 排期 / 快速评估 / 延后 |

-   双轴只作用于 `backlog.md` 的「短期 / 一次性候选」区（待上收候选 + 延后保留池）；长期主线与「待跟踪与上游反馈登记」属于管理 / 观察项，不参与排序。
-   象限只是推进顺序建议，**不构成启动授权**；仍需用户授权、阶段容量准入与 §3.4 插队例外判断。
-   评分不做存量全量回填：新登记必填，存量在触碰（改写 / 评估 / 上收）时补齐。

## 3. 评分锚点与象限

锚点、象限动作与复核触发以规划规范 §3.5 为唯一事实源；本文只记录取舍理由，避免双写。

## 4. 留痕与边界

-   候选上收时在 `roadmap.md` 阶段条目写入一行 `双轴: 重要 x / 紧急 y / 建议 z（日期）` 作为排序快照；`todo.md` 不复制分数。
-   评分是当期判断：阶段登记前复核，每季度例行复核；象限或分数变化必须更新说明依据。
-   守卫：`tests/scripts/backlog-priority.test.ts` 校验分数范围、象限建议、说明依据，并阻止 `todo.md` 复制双轴分数。

## 5. 未采用方案

-   用双轴替换 4 维矩阵：矩阵承载成本 / 风险，双轴不承载，替换会丢失准入判断。
-   由矩阵 `Score` 推导双轴：两者输入不同，推导会让紧急度被价值稀释。
-   一次性回填全部 9 条短期候选（2026-11-26 快照）：长期主线与跟踪项不参与排序，全量回填只会制造无效维护。
