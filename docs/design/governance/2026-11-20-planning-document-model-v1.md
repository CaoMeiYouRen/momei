# 规划文档模型 v1 落地说明（粒度 / 进度 / 归档）

## 1. 背景与问题

上游提案 `docs/proposals/2026-11-20-planning-doc-model.md`（`CaoMeiYouRen/cmyr-skills-agents`，commit `0382b75`）指出四个项目的规划文档在粒度、进度可见性与归档载体上各自演进。对照 momei `396ed65b` 的现状：

-   大条目与小条目没有分层定义，`todo.md` 的验收单位与 `commit`、审计范围对不齐。
-   阶段容量正文写“5-6 项”，但没有上限与第 7-8 项的例外说明。
-   `todo.md` 只有状态图例，没有阶段进度表；判断进度必须逐条读正文。
-   `todo-archive.md` 的索引是标题目录，不是可机检的表格。
-   归档块字段靠各阶段自行组织，没有统一必填项。
-   分片命名已全部符合 `<起>[-<止>]`，不需要改名。

本说明记录 momei 对 issue #1071 的采纳范围、决策与验证口径；规范正文见 [规划文档模型 v1](../../standards/planning-docs.md)。授权来源为 issue #1071；当前无进行中阶段，本批不写入 `todo.md` 正文。

## 2. 采纳范围

| 提案项 | 结论 | 落点 |
| :--- | :--- | :--- |
| 小条目分层 | 已采纳 | 大条目保留 8 要素，小条目只写 4 项；`todo.md` 与归档块不复制大条目字段 |
| 数量约束 | 已采纳 | 大条目默认 4-6、上限 8；小条目 1-5 / 大条目，单阶段 ≤20、建议 10-15 |
| 进度表 | 已采纳 | `todo.md` 当前阶段头部 6 列；无进行中阶段保留空表头或占位行 |
| 索引表 | 已采纳 | `todo-archive.md` 的标题目录改为 4 列表格，倒序覆盖 14 个 todo 分片 |
| 归档块字段 | 已采纳（前向） | 新增 / 迁移块 6 项必填；存量归档块冻结，不回改正文 |
| 分片命名 | 无需动作 | 14 个 todo 分片与 20 个 roadmap 分片均已符合命名式 |
| 机检 | 已采纳 | 新增 `docs:check:planning-docs`，覆盖进度表行数、索引一致性与 v1 归档块字段 |

## 3. 四个研判问题

### 3.1 主窗口阈值保持 500 还是降到 400

**结论：保持 500。**

-   `todo-archive.md` 改动前基线（`396ed65b`）为 366 行（`wc -l`）/ 367 行（`docs:check:line-count`）、11 个近线归档块，低于 500 健康线；行数仍有约 4 个阶段的余量。
-   主窗口按行数治理，不按块数治理。块数受每阶段条目数影响，单独设 4-6 块会迫使稳定阶段提前迁出，增加无阅读收益的机械搬移。
-   400 作为上游模板默认值保留为参考；若后续单块体量持续变小、11 块仍能稳定在 400 行以内，再评估把健康线降到 400。
-   阈值的执行单点仍是 `scripts/docs/check-line-count.mjs`；规范与 `archive/index.md` 保留当前值副本，数值变更须与脚本同名目标同步。

### 3.2 标题目录改表格是否影响锚点与外部引用

**结论：无影响。**

-   全仓检索 `todo-archive.md#` 锚点引用为 0；现有引用均为文件级链接（如 `../todo-archive.md`）。
-   标题目录本身不产生锚点，归档分片路径不变，因此外部深链不受影响。
-   表格内的归档文件链接改为单行 4 列，链接目标仍是 `./archive/todo-archive-phases-*.md`；`docs:check:links` 复跑为 0 失效。

### 3.3 小条目 4 项与现有 AC 具体化是否冲突

**结论：不冲突，按“大条目保留、小条目摘要”合并。**

-   `planning.md` 的验收标准具体化约束作用于大条目：8 要素中的“验收标准”仍需覆盖执行范围、非目标、最小验证矩阵 / 证据落点与回滚边界。
-   小条目只写目标、验收摘要、交付物、依赖；验收摘要必须回指大条目的验收标准，不复制 8 要素。
-   这样既保留原有 AC 判别力，又避免 `todo.md` 与归档分片因重复字段体量翻倍。

### 3.4 backlog 候选字段是否本期规范化

**结论：延后。**

-   `backlog.md` 改动前基线（`396ed65b`）为 228 行（`wc -l`）/ 229 行（`docs:check:line-count`）、21,238 字符，处于健康窗口，没有因体量必须拆分的压力。
-   候选字段规范化需要先确定“长期主线”和“短期候选”各自的必填集与迁移口径，属于独立治理批次，混入本提案会扩大改动面。
-   已登记到长期主线 #6「文档事实源、翻译与分层归档治理」的下一次切片方向，后续随该主线评估。

## 4. 机检口径

新增 `scripts/docs/check-planning-docs.mjs` 与 `pnpm docs:check:planning-docs`：

1.  **进度表**：`todo.md` 当前阶段第一张表必须为 6 列；数据行数等于正文顶层 `- [ ]` / `- [x]` 大条目数；`状态` 只允许四值；`小条目` 必须为 `N/M`。
2.  **归档索引**：`todo-archive.md` 的索引表必须为 4 列、按阶段倒序、覆盖 `docs/plan/archive/todo-archive-phases-*.md` 全集、无重复，文件名与阶段区间一致。
3.  **v1 归档块**：带 `> **归档块模型**: v1` 标记的归档块必须包含 6 项必填字段；未标记的存量块不参与断言。

机检接入 `docs:build`、发版前检查与周级回归；只读、无副作用。归档正文的语义质量仍由人工 `Review Gate` 判定。

## 5. 影响面与回滚

本批为单一交付（规范 + 规划表迁移 + 只读机检 + 测试 + 门禁接线），拆分会让“规范先于机检”或“机检先于模型”的中间态与门禁结论不一致，因此按单次治理交付登记；不属于业务代码批次。

-   **规范**：`planning.md` 只改容量口径、验收分层、进度表与归档字段指针；细节全部落在 `planning-docs.md`，避免规范主体继续膨胀。
-   **规划文档**：`todo.md` 增加空进度表；`todo-archive.md` 索引改表格；`archive/index.md` 同步阈值口径与分片登记。
-   **门禁**：新增只读检查与单测；不修改现有 `docs:check:*` 的判定语义。
-   **回滚**：规范与表格类改动 revert 对应提交；索引形态恢复标题目录即可，归档分片本身不动；已按 v1 产出并归档的阶段不回改。
