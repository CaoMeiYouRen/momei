# 规划文档模型 v1（粒度 / 进度 / 归档）

本文档定义 `docs/plan/` 的文档形态与机检口径，是 [项目规划规范](./planning.md) 的下位模型说明。阶段准入、评估矩阵、阶段归档流程与下一阶段闸门仍以 `planning.md` 为准；两者冲突时，流程与门禁取 `planning.md`，表格与字段形态取本文档。

## 1. 适用范围与原则

适用于 `docs/plan/todo.md`、`roadmap.md`、`todo-archive.md` 与 `docs/plan/archive/`。

1.  **前向统一**：新阶段按 v1 执行；存量只做机械改名（路径与因路径变化产生的链接 / 锚点），不改正文。
2.  **模型统一、参数自理**：阶段编号、ID 格式、主窗口阈值与容量单位由项目自定；项目内唯一性由项目保证。
3.  **不新增事实源**：不引入第四个规划载体；`backlog.md` 继续只承担候选池。

## 2. 三级粒度

| 层 | 定义 | 必填字段 | 提交 | 审计 |
| :--- | :--- | :--- | :--- | :--- |
| 阶段 | 一次授权范围 | 目标 / 容量基线 / 执行顺序 / 不做范围 | — | — |
| 大条目 | 可独立验收的交付包 | 8 要素 | 1-N 次 | 至少 1 轮 |
| 小条目 | 可独立提交的最小单元 | 目标 / 验收 / 交付物 / 依赖 | 1 次 | 跟随提交 |

**大条目 8 要素**：目标、优先级、范围、验收标准、不做什么、依赖、交付物、风险。验收标准必须覆盖最小验证矩阵 / 证据落点与回滚边界。

**小条目 4 项**：目标、验收摘要、交付物、依赖。其余字段继承大条目；验收摘要只写可判定的结果并回指大条目的验收标准，不复制 8 要素。

**数量约束**：

-   单阶段大条目默认 **4-6 项**，上限 **8 项**；使用第 7-8 项时必须在阶段头写明“为何不拆成两个阶段”。8 是上限，不是目标值。
-   每个大条目 1-5 个小条目；单阶段小条目总数 **不超过 20 项**，建议 10-15 项；超过 15 项需说明为何不拆阶段。
-   超出容量时按“进一出一”移出低优先级内容，不靠压缩验收标准腾位置。

**提交与审计**：小条目默认独立提交、独立审计；仅强耦合（同一文件、同一契约变更、必须同一 `commit` 才可编译）时合并批次，并在条目内写明合并理由。

**ID**：建议 `<大条目ID>.<序号>`（如 `80.1.3`），不要求跨项目一致；项目内必须唯一，且能在进度表“提交”列定位到实际 `commit`。存量 ID 不改。

## 3. 进度表

`todo.md` 当前阶段标题下第一张表固定 6 列，项目可增补列：

| 大条目 | 小条目 | 状态 | 提交 | 审计 | 容量（计划→实际） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 80.1 CLI 断点续传 | 3/3 | 已闭环 | `bc93c165` | R1 Pass | 3 → 3 commits |

-   行 = 大条目；`小条目` 列写“已闭环 / 总数”。
-   `状态` 只取四值：`未开始` / `进行中` / `已闭环` / `已阻塞`。
-   `提交` 列写实际 `commit` 短 hash（多个用 `、` 分隔）；未提交写 `待提交`。
-   `容量` 默认单位为 commits，项目可改用 files 或行数；写明计划值与实际值。
-   无进行中阶段时保留空表头，或使用一行全 `—` 的占位行；占位行不计入正文大条目数。
-   机检口径：表行数 = 当前阶段正文顶层 `- [ ]` / `- [x]` 大条目数；`已闭环` 行数 = `[x]` 大条目数；状态值必须在四值内；大条目 ≤8（第 7-8 项需写不拆理由），小条目总数 ≤20。

## 4. 归档载体

| 项 | v1 约定 |
| :--- | :--- |
| 路径 | 主文件 `docs/plan/todo-archive.md`，分片目录 `docs/plan/archive/` |
| 主文件职责 | 索引表 + 近线窗口；行数阈值由项目自定 |
| 分片命名 | `todo-archive-phases-<起>[-<止>].md`、`roadmap-phases-<起>[-<止>].md`；区间连续 |
| 分片粒度 | todo 与 roadmap 分片分开，不合并为同一文件 |
| 索引表 | 固定 4 列：阶段 / 主题 / 归档文件 / 归档日期；倒序、覆盖全部分片、无重复、无正文 |
| 归档块必填 | 6 项：阶段名与时间 / 大条目清单与状态 / 提交清单 / 质量门结果 / Review Gate 结论与轮次 / 未覆盖边界 |

**本仓参数**：

-   主窗口阈值以 [项目规划规范 §4.4](./planning.md) 与 `pnpm docs:check:line-count` 的单点为唯一口径；行数是硬约束，归档块数量只作观察项。
-   新增分片必须按命名式创建并登记索引；存量分片不改名。

**归档块模板**：

```md
## 第八十一阶段：<主题>（已审计归档）

> **归档块模型**: v1

-   **阶段名与时间**: 第八十一阶段 · 2026-12-01 ~ 2026-12-03
-   **大条目清单与状态**: 1. <标题>（[x]）；2. <标题>（[x]）
-   **提交清单**: `<hash>`（条目 1）、`<hash>`（条目 2）
-   **质量门结果**: lint / typecheck / 定向测试 / coverage / E2E
-   **Review Gate 结论与轮次**: R1 Reject → R2 Pass
-   **未覆盖边界**: <残余风险或后续观察项>
```

v1 之前形成的归档块冻结，不按本模板回改；新增与迁移块按 6 项填写，并保留 `> **归档块模型**: v1` 标记供机检识别。

## 5. 机检

`pnpm docs:check:planning-docs`（`scripts/docs/check-planning-docs.mjs`）执行三类检查：

| 规则 | 判定 | 分档 |
| :--- | :--- | :--- |
| 进度表存在且行数一致 | 行数 = 正文大条目数，状态值合法，`小条目` 符合 `N/M`；大条目 ≤8（7-8 需写不拆理由），小条目 ≤20 | error |
| 归档索引一致性 | 4 列、倒序、覆盖全部 `todo-archive-phases-*.md`、无重复、文件名匹配命名式 | error |
| v1 归档块字段 | 带 `归档块模型: v1` 标记的块 6 项齐全 | warning |

检查已接入 `docs:build`、发版前回归与周级回归；只读、无副作用。归档正文语义、`Review Gate` 结论真实性与小条目完成质量仍由人工 `Review Gate` 负责。

## 6. 变更与回滚

-   规范与表格类改动：revert 对应提交。
-   索引形态调整：恢复为标题目录即可，归档分片本身不动。
-   已按 v1 产出并归档的阶段不回改。
